# Machines and challenges

## Objective

Implement reusable machines, isolated decisions, tournaments, challenge links, and required hosted tracing.

## Relevant specification sections

Sections 1, 2, 5, 6, 8, 10, 11, 12, 13, and the new machine release contract apply.

## Files and contracts changed

The machine release contract defines the new public application. Existing match contracts remain available for historical records.

## Decisions and reasons

Generate code once to provide stable machine versions. Use fresh Monty sessions to prevent hidden state between decisions.
Use a fixed tournament to reward points across varied opponents. Use SQLite to preserve machines and replays.

## Simplicity review

The current requirement needs generated code execution and two machine participants.
The existing model player makes a model request each round and cannot satisfy this requirement.
One machine module owns execution and tournament functions. One store owns the new records.
The added boundaries can fail during generation, execution, storage, or telemetry export.
Tests cover isolation, limits, scoring, publication contracts, and HTTP boundaries.
FastAPI provides transport validation. Uvicorn serves the application. Monty executes untrusted code.
